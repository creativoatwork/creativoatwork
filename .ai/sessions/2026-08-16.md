# 2026-08-16 — CCOS 2.4 upgrade and Codex adoption

Documentation and configuration only. No source file, dependency, or deployment was touched.

## What was asked

Update the repository to CCOS 2.4 from a supplied `CCOS_v2.4.md`, then install Codex.

## The false start

The session began against a working copy at `879f567` — 22 commits behind `origin/main`.
`git status` was clean, which was read as "current". It was not.

Everything shipped since 2026-08-05 was therefore invisible: prerendering, the FAQ and legal
pages, the crawler files, the consent banner, rate limiting, the rebuilt Work grid, the WebP
previews. The session concluded "no CCOS present, this is a greenfield adoption" and wrote a
`CONTEXT.md`, `decisions.md`, and `backlog.md` describing a site that no longer existed — plus
a `.ai/CLAUDE.md` that would have overwritten the real project rules with the CCOS standard
text. Two commits were made locally (`6bb6d04`, `5c2d11e`).

`git push` was rejected as non-fast-forward, which is the only reason this was caught before
it reached the remote. Nothing was pushed; the remote was never affected.

**Recovery:** the stale commits were parked on branch `ccos-stale-attempt`, `main` was
hard-reset to `origin/main`, and the upgrade was redone against real state.

**The lesson is in `decisions.md`:** a clean `git status` says nothing about whether the branch
is behind. CCOS §8's "confirm Git state" means fetching first.

## Codex

Already installed system-wide (`/usr/local/bin/codex`, `codex-cli 0.147.0`) and authenticated
via ChatGPT, so no `npm install -g @openai/codex` was needed. Added the plugin via
`/plugin marketplace add openai/codex-plugin-cc` and `/plugin install codex@openai-codex`.

`codex-companion.mjs setup --json` reported `ready: true`, auth verified, advanced runtime
available, session runtime in `direct` mode (starts on demand). `reviewGateEnabled: false`.

**Known gap:** the `openai-codex` marketplace is registered at user level, not in this repo's
`.claude/settings.json`. `enabledPlugins` therefore references a marketplace the repository
does not declare, so a fresh clone on another machine will not resolve the plugin until the
marketplace is added there too. Left as-is rather than committing machine setup into the repo.

## /admindash built

Private multi-project dashboard, implemented after five spec revisions and four adversarial
Codex reviews. The spec is `docs/superpowers/specs/2026-08-16-admindash-design.md`.

**What the reviews changed, in order.** v1 proposed a `/inspect` endpoint on the Cloudflare
Worker that would fetch arbitrary domains to infer their stack; Codex returned 15 HIGH findings,
eight of which existed only because of that endpoint. The operator asked whether it could be
simplified, and cutting `/inspect` entirely removed them — the dashboard now touches no
Cloudflare infrastructure at all. v3's CSP omitted `https://apis.google.com` from `script-src`
and would have shipped a dashboard nobody could sign into. v4's restore procedure deployed
*relaxed* production rules for the duration of a restore. v5 fixed that by loosening the create
rule instead, and Codex then found the resulting `setDoc` restore was neither idempotent nor
convergent, because `setDoc` on an existing document is an update.

The last one is the lesson: three rounds of hardening a procedure meant the design was wrong,
not under-defended.

**Built:** two Vite entries; `src/admin/**` (auth, data layer, table, filters, form, modal,
delete dialog, export); `firestore.rules` with full field/enum/length/timestamp validation;
47 emulator-backed rules tests; `scripts/restore-projects.mjs`; Hosting rewrites, CSP and
`X-Robots-Tag`; `Disallow: /admindash`.

**Verified, actually run:**

- `npm run build` — clean, `prerender: injected 27,915 bytes` (unchanged)
- `npm run test:rules` — **47/47 pass** against the Firestore emulator, exercising the
  production rule text with only the UID substituted
- Marketing dependency closure walked from `dist/index.html`: `main.css` + shared React +
  `main.js`, **no Firebase**. All 745KB of SDK is in the admin-only chunk.
- Marketing CSS: **zero** selectors added versus the pre-change baseline. It got 4KB *smaller* —
  scoping `@source` stopped Tailwind scanning `dist/` and `public/` build artifacts and emitting
  12 phantom utilities (`.transition`, `.filter`, …) that no source file used as a class.
- Marketing JS 168,086 bytes vs 168,120 before.
- `dist/admindash.html` ships an empty root; prerender never touches it.

**Not verified:** nothing has been deployed, no browser run, and the CSP has not been exercised
against a real sign-in. Firestore is still not provisioned.

**Not done, needs the operator:** enable the Firestore API and create the database; enable the
Google *and* Email/Password providers; deploy rules; sign in to read the UIDs and replace the
placeholders in `firestore.rules`; verify the CSP on a preview channel before promoting.
