# 2026-08-16 — CCOS 2.4 upgrade and Codex adoption

Documentation and configuration only. No source file, dependency, or deployment was touched.

## What was asked

Update the repository to CCOS 2.4 from a supplied `CCOS_v2.4.md`, then install Codex.

## The false start

The session began against a working copy at `879f567` — 22 commits behind `origin/main`.
`git status` was clean, which was read as "current". It was not.

Everything shipped since 2026-08-05 was therefore invisible: prerendering, the FAQ and legal
pages, the crawler files, the consent banner, rate limiting, the rebuilt Work grid, the WebP
previews. The session concluded "no CCOS present, this is a greenfield adoption" and wrote a
`CONTEXT.md`, `decisions.md`, and `backlog.md` describing a site that no longer existed — plus
a `.ai/CLAUDE.md` that would have overwritten the real project rules with the CCOS standard
text. Two commits were made locally (`6bb6d04`, `5c2d11e`).

`git push` was rejected as non-fast-forward, which is the only reason this was caught before
it reached the remote. Nothing was pushed; the remote was never affected.

**Recovery:** the stale commits were parked on branch `ccos-stale-attempt`, `main` was
hard-reset to `origin/main`, and the upgrade was redone against real state.

**The lesson is in `decisions.md`:** a clean `git status` says nothing about whether the branch
is behind. CCOS §8's "confirm Git state" means fetching first.

## What was actually done

**Added**

- `.ai/CCOS.md` — the CCOS 2.4 standard, verbatim. Placed here rather than at `.ai/CLAUDE.md`,
  which was already occupied by the project rules; see `decisions.md`.
- `CLAUDE.md` at the repository root — imports `.ai/CCOS.md` and `.ai/CLAUDE.md`, states the
  precedence between them, indexes the memory files, and flags the three repo-specific traps
  (prerender step, Work-grid constraints, the Capabilities list).
- `.ai/sessions/2026-08-16.md` — this file.

**Changed**

- `.ai/CLAUDE.md` — added the pointer to `CCOS.md` and the precedence rule. Corrected the
  stale claim that "the honeypot is the only abuse control today. There is no rate limiting" —
  the 3/min per-IP limiter shipped 2026-08-05 and `CONTEXT.md` documented it correctly all
  along. The replacement keeps the honest framing: per-colo, fails open, caps spend rather
  than guaranteeing a quota.
- `.ai/decisions.md` — two entries (CCOS adoption; Codex as reviewer), plus the stale-checkout
  process failure.
- `.ai/backlog.md` — new "Process" section: the disabled review gate, and the memory-drift
  observation.
- `.claude/settings.json` — enables `codex@openai-codex`.

**Preserved unchanged:** `CONTEXT.md`, `sessions/2026-08-05.md`, `PRODUCT.md`, `README.md`, all
of `src/`, `worker/`, `public/`, `scripts/`, and every deployment config.

## Codex

Already installed system-wide (`/usr/local/bin/codex`, `codex-cli 0.147.0`) and authenticated
via ChatGPT, so no `npm install -g @openai/codex` was needed. Added the plugin via
`/plugin marketplace add openai/codex-plugin-cc` and `/plugin install codex@openai-codex`.

`codex-companion.mjs setup --json` reported `ready: true`, auth verified, advanced runtime
available, session runtime in `direct` mode (starts on demand). `reviewGateEnabled: false`.

**Known gap:** the `openai-codex` marketplace is registered at user level, not in this repo's
`.claude/settings.json`. `enabledPlugins` therefore references a marketplace the repository
does not declare, so a fresh clone on another machine will not resolve the plugin until the
marketplace is added there too. Left as-is rather than committing machine setup into the repo.

## Validation

No code changed, so `npm run build` was not run — the build is unaffected by documentation.
Verified instead: `git diff` reviewed in full, the new files grep clean for key and credential
patterns, and the CCOS text matches the supplied source byte-for-byte.

Not claimed: no Codex review of this change. Under CCOS §14 a documentation-and-configuration
change sits in the skippable band, and Codex was not installed for most of the session anyway.
